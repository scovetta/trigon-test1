Rebuild results

Trigon rebuilds published packages from the source they claim to come from, compares each rebuild with the artifact the registry serves, and signs what it finds. This repository holds 11 records about 11 artifacts of 11 packages, as of 2026-10-02 13:14 UTC.

Every result is a record signed by the operator's attestation key and logged in an append-only log anyone can verify. These pages are generated from that log, and prove nothing on their own: whoever can push to this repository could change a page, but not a record or the log. To rely on a result, check it with the trigon command-line tool, as Verify it yourself shows.

Verify it yourself

The trigon command-line tool checks every signature and recomputes the log from the keys you pin. It trusts nothing on this page.

Add this repository as an evidence source, pinned by its two keys, and sync it: Trigon clones it and verifies its whole log. Then ask about a package, or a file you already hold. Compare the keys with ones the operator published somewhere other than this repository: a page here, and the copies in keys/, are only as good as the repository.

Every answer names the checkpoint it was given from. When these pages were generated, the log was at

A line with the same size and another root, from anyone, is proof that the log was rewritten. A record's page has the command that would falsify it, which re-derives the comparison from the two artifacts.

What the results mean

The comparison ends in one of four outcomes, strongest first, or the run is void.

resultmeans
✔︎exactThe rebuild is the published artifact, byte for byte, before any stabilizer ran.
✔︎normalizedOnce both were stabilized they are identical, and every stabilizer that fired ships with Trigon and is no riskier than metadata: timestamps, ordering, file modes.
◐normalized_with_caveatsOnce both were stabilized they are identical, but a stabilizer that fired changes content, or a person or a model wrote it. Read what fired.
✖︎divergentOnce both were stabilized they still differ, and the record names which files. A divergence is a public claim about somebody else's package, so each one names where to dispute it.
⊘voidThe run proves nothing about the package, and the record says why: the build could reach the open internet, it reached the artifact under test, or a stabilizer a person or a model wrote fired.
–withdrawnThe operator said an earlier result was wrong. Both stay in the log.
!fails verificationA record the log holds whose file is missing, or does not verify. Every client reports it, since either may be an attack.

Build logs, network transcripts and model transcripts are not published: they are unredacted and may hold credentials. Each record signs their digests, and a record's page shows them.
